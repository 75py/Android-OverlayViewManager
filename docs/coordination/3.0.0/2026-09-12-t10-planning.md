## API・利用例の契約C1

Applicationでinit、OverlayPermissionとActivity Resultによる設定画面復帰後の権限再確認、両scopeのOverlaySpec生成・show/update/dispose結果の扱いを示す。状態はATTACHEDを使い、clickはView、dragはDRAGGABLE、brightnessはActivity scopeのspecに設定する。screenのslider範囲はhost windowから得る。allowOutsideBoundsはシステムバー領域への表示を保証しない。Kotlinはdefault引数/copyを示す。

## Codexの訂正と明示合意

msg_0467e0d559b0で以下を訂正して受諾、msg_e142c8c8ccb0でClaudeがK1〜K7を拘束条件として明示合意した。

1. AGP9.2.1 built-in Kotlin2.2.10があるのでkotlin.android plugin・依存追加は不要。既存Activity1つを妥当な範囲でKotlin化（Sample1Activity案）しJava/data binding相互利用をコンパイルする。
2. state/lastFailureはthread-safeな読み取り例外。spec/view/更新操作はmain-thread。
3. application overlayのdispose失敗では唯一のhandleを捨てず、retry可能な状態を保持する。設定画面後のshowは明示的host/user要求に従い、permission loopや自動retryを作らない。
4. assetsとsourceの文字列一致だけをassertするmirror testは作らず、実コンパイル済み例との照合・参照/リンク確認を行う。テストは挙動を優先する。
5. deprecated検索はreceiver/typeを区別する。Android View.setOnClickListenerやsetAlphaまで除去対象にしない。
6. 見た目の変更は専用AVDで最低限のsmoke/screenshotをPRへ添える。既存emulator-5554は触らない。cross-UIDを含む完全な端末matrixはT12のまま。
7. host windowのboundsは互換fallbackを含め、overlay権限に依存させない。システムバー上の表示を保証しない。

T10aの受け入れはsample assemble・unit test・lint・androidTest APK buildとsmoke/screenshot、旧OverlayView/Manager bridge利用の除去。T10bは両scopeの実例・Java/Kotlin移行表・Timber dispose・対応OSと制限を含み、T10aの最終snippetに合わせる。
