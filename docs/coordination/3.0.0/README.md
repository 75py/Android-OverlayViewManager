# 3.0.0 司令塔間のやり取り・判断ログ

このディレクトリをGit管理し、後から「誰が何を提案し、どう応答し、なぜ決めたか」を振り返れるようにする。2026-09-12 JSTに開始指示を受領し、CodexとClaudeの協議を開始した。

## 記録方法

- 話題ごとに `YYYY-MM-DD-<task-id>-<topic>.md` を作る。ユーザー指示による準備は `prep` を使う。
- 各発言の日時（タイムゾーン付き）、司令塔名、内容の要旨を時系列で残す。逐語転載でないものは要旨と明記する。
- 提案だけでなく相手の返答、異論、選択肢、判断根拠、未解決の質問、結論を残す。機密値や無関係な端末出力は記録しない。
- OrcaのメッセージID・Task/Dispatch、PR URL・head SHAを参照する。ローカル端末ハンドルだけに依存しない。
- 「ユーザー指示」「一方の提案」「回答待ち」「双方合意」「撤回・変更」を区別する。実在しない会話や承認を補わない。
- 過去の判断を上書きせず、変更理由と旧判断へのリンクを付けて追記する。
- 各司令塔は自分のworktreeで記録案を作り、Codexが共有計画・ログの統合を直列化する。同じログを並行編集しない。
- 合意を担当へ渡す前、レビュー結論時、統合時に記録する。関連PRまたは文書PRでコミットし、実装開始後のマージは相互承認を経る。
- 相互APPROVEの記録は対象PR/head SHAと元のレビューを参照する。Markdownの記載だけでレビュー済み扱いにしない。
- `V3_0_0_PLAN.md` も節目に更新する。ユーザー許可による準備用先行コミットは、未実施の相互レビューとは区別して記録する。

## テンプレート

```markdown
# <Task ID>: <話題>

- 状態: 提案 / 回答待ち / 双方合意 / 撤回・変更
- 関連タスク:
- 記録担当:
- 関連PR / head SHA:
- Orcaメッセージ / Task / Dispatch:

## 背景・選択肢

## やり取り（発言要旨）

| 日時・タイムゾーン | 発言者 | 提案・返答・異論 | 根拠・元メッセージ |
| --- | --- | --- | --- |

## 判断結果・理由

## 未解決事項・次の担当

## 計画・実装・検証への影響

## 変更履歴・後続判断
```
